- 2026-09-25: Why the console scraping never worked, for whoever picks this up again. Four separate faults, in the order they had to be found: (1) a JUL Handler was attached to the logger named "Minecraft", which is a *sibling* of the plugin loggers rather than their parent, so it never saw a line from AngleGuard or TotemGuard; (2) Paper sets `useParentHandlers=false` on plugin loggers, so moving the handler to the root logger did not help either; (3) the `matches(String)` gate on every log provider was declared abstract and then never called, so each provider parsed every other anticheat's alerts and filed them under its own name; (4) the log-file tailer started reading at byte 0, replaying the entire server log on every start. The scraper was never proven live: the only evidence offered was a line count, and a one-shot full read produces exactly the same number. `/gildedcore status` never separated lines *read off disk* from lines *delivered to providers*, so a dead drain task looked identical to a working one.
- 2026-09-25: Process note, and the actual lesson. Every fix in that sequence was written from a theory about how logging worked and none of them were verified on a server, so each one cost the user a restart and a screenshot. The pattern test, the byte-level tailer test and the format test all passed while the feature was still completely broken, because every one of them tested a piece in isolation and none tested the seam between the plugin's own logger and the thing reading it. What would have found it on the first try: publish a log record from a second plugin and assert it arrives, which needs no server and no anticheat installed. Anti-pattern worth naming - reading a plausible counter as proof of behaviour. `Console source: 1632 lines` looked like proof of scraping and was equally consistent with a single full read of a dead file.
